# SkillWatch UX design — approachability for less-technical users

**Date:** 2026-07-11
**Status:** Path A approved for build; Path B specified but NOT to be built (demand-gated).
**Scope framing:** "as approachable as an honestly-scoped CLI + docs can be" — measured by
concrete UX gains, **not** by any claim that a non-expert can now triage security alerts
unaided.

---

## 1. The honest problem statement

SkillWatch is a Python CLI that monitors the external URLs AI-agent skills and MCP tools
point to, and flags suspicious changes. Two facts bound what "usable by non-technical
users" can mean:

1. **The medium.** A terminal tool (`pip install`, `skillwatch scan`, cron/CI) assumes
   terminal literacy. Best-practice CLI UX raises the floor for *semi-technical* users; it
   does not remove the terminal prerequisite for *non-terminal* users.
2. **The task.** Triaging alerts where ~1 in 5 is a false positive is expert judgement.
   Plain language helps a reviewer, but cannot fully substitute for the judgement.

Conclusion (evidence-backed, see §2): copy-polish and `/humanizer` make SkillWatch **more
approachable**; they do not make it usable by a truly non-technical person. That would need
a different surface (Path B), which is premature at 0 users.

## 3. Paradigm decision (2026-07-11)

- **Path A — raise the CLI + docs to their accessibility ceiling.** APPROVED — build now.
- **Path B — a non-technical surface (GUI/hosted).** Specified in §6, **not built**
  (demand-gated: 0 users; also still faces the comprehension ceiling).
- **Success bar:** direction-of-travel (concrete UX gains), not a hard "non-expert can
  triage unaided" claim.

## 4. Path A — change-set (build now)

Each item cites the principle it implements.

1. **Plain-language alert layer (centerpiece).** Map each of the 13 flag codes to plain
   English, plus a universal "what to do". Render in terminal output; keep the raw code in
   parentheses for power users; JSON output unchanged. *(NN/g #2, #9; clig.dev "rewrite for
   humans".)* See §5 for the map.
2. **Examples-first help.** argparse epilogs with worked examples on the main command and
   `add`/`scan`/`alerts`; a 3-step quickstart on the no-arg screen. *(clig.dev, lucasfcosta,
   ThoughtWorks all: "lead with examples".)*
3. **First-run & next-step nudges.** Tighten empty states; make the no-arg screen a real
   quickstart. *(clig.dev "suggest next steps"; lucasfcosta "reduce time-to-value".)*
4. **Actionable errors.** Copy pass so each error states the fix (SSRF block explains it is
   intentional and why; file-not-found suggests checking the path). *(clig.dev, NN/g #9.)*
5. **Progress feedback in `scan`.** A `[i/total]` counter; `--quiet`/JSON unaffected.
   *(lucasfcosta, ThoughtWorks.)*
6. **Docs pass + `/humanizer`.** Re-run `/humanizer` over README, CLI strings, and
   `docs/index.html`; add a plain-language **"Understanding your alerts"** guide (the §5
   map) — the human-review scaffolding the tool currently lacks.
7. **Honesty guardrail.** Add an explicit "Who this is for / who it's not for" line; keep
   all framing at "more approachable", never "now non-technical"; keep the 13-code / 32-
   pattern numbers in sync with code.

## 5. The plain-language flag map (single source of truth: `detector.py`)

| code | severity | plain-language |
|---|---|---|
| new_exec_command | critical | Added a command that could download or run software |
| prompt_injection | critical | Added wording that could tell an AI assistant to ignore its instructions |
| suspicious_script | critical | Added a script that can read cookies, send data, or run code |
| data_uri_embed | critical | Embedded hidden content (a `data:` frame) that can run in a browser |
| new_base64 | warning | Added a long encoded string that could hide instructions or code |
| credential_reference | warning | Now mentions passwords, API keys, or tokens |
| new_domains | warning | Now links to web addresses it didn't reference before |
| unicode_homoglyph | warning | Uses look-alike letters (e.g. Cyrillic mimicking English) — a disguise trick |
| data_uri_payload | warning | Contains a `data:` URL with runnable content |
| meta_refresh_redirect | warning | Added an automatic redirect to another address |
| major_deletion | warning | More than half the page's content was removed |
| iframe_detected | warning | Added an embedded frame from another source |
| hidden_content | info | Added text that's hidden from view but still readable by software (inline and `<style>`-block CSS plus the HTML `hidden` attribute; screen-reader idioms and external stylesheets excluded — see PATTERNS.md) |

**Universal "what to do":** *If you didn't expect this change, stop using the skill or tool
that points here and review the change below before trusting it again.*

A test asserts every code the detector can emit has a map entry (prevents drift).

## 6. Path B — spec only (do NOT build; demand-gated)

A minimal non-technical surface, recorded so it is shovel-ready **if** demand appears:

- **Shape:** hosted or desktop GUI. "Paste a skill or repo → we watch it." No terminal, no
  cron.
- **Alerts:** email/notification written as "this page changed suspiciously — here's what,
  and here's what to do", severity as plain words, the diff hidden behind "show technical
  detail".
- **Hard caveat:** even here, the security judgement must be pre-digested for the user; a
  raw diff does not clear the comprehension ceiling.
- **Gate:** not to be built until there is real demand evidence (the project's standing
  "don't build before demand" stance; currently 0 users).

## 7. Validation / verify plan

- Every change ships with the verify gate green: `pytest` (≥ current count), `ruff`, `mypy`
  (strict), and the `--cov-fail-under=90` floor.
- The plain-language map gets a drift-proof test (every emitted code has an entry).
- Before/after terminal output captured in the PR.
- Numbers (13 codes / 32 patterns) kept in sync with code.

## 8. Explicitly out of scope

- No detection-behaviour change (settled constraint: regex/DOM only, no ML/LLM).
- No new runtime dependencies.
- Path B implementation.
